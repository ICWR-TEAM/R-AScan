# 2026-06-27

## Changed

- Hardened `top_25_owasp_full_scanner.py` against false positives with
  per-scan canaries, stricter SQLi/LFI/RCE/Open Redirect checks, baseline-aware
  signatures, and low-confidence potential status for weak SSRF/XSS signals.
- Hardened `xss.py` so raw or escaped reflection is reported as potential, while
  confirmed reflected XSS requires an executable SVG handler context. DOM XSS
  signals now require both a controllable source and dangerous sink.
- Hardened `broken_access_control.py` with baseline body storage, response
  similarity checks, denial/login suppression, and low-confidence potential
  reporting for unauthenticated access signals.
- Hardened `http_smuggler.py` with control requests and probe-specific
  validation; keyword-only responses no longer count as smuggling anomalies.
- Hardened `ldap_injection.py` by comparing wildcard payload behavior against a
  random control username and reporting only LDAP-specific error differentials
  as low-confidence potential findings.
- Moved the HTML report document structure and CSS into
  `r_ascan/resources/report_template.html`; `r_ascan/reporting/html.py` now
  loads the resource template and replaces escaped dynamic placeholders.
- Expanded `r_ascan/resources/report_template.html` into a PTES-style report
  structure with executive summary, scope, methodology, detailed findings,
  scanner execution, and a findings summary table containing Title, CVSS v3.1
  Score, CWE/CVE, Affected Host, Summary, Impact, and Remediation.
- Added POC and Evidence columns to the PTES-style findings table. The HTML
  renderer now builds scanner-aware `curl` POC commands and concise evidence
  summaries from normalized finding data, including special handling for HTTP
  smuggling, LDAP injection, and security header checks.
